# 发送缓冲保护

Node Plugin、Web Plugin 和 PI 使用有界发送队列，不需要修改现有发送 API。

- 每条连接的 SDK 队列与传输待发送数据合计最多 16 MiB，SDK 队列最多 1024 条消息。单条消息也受 16 MiB 限制（Node 包含 WebSocket 帧头）。超过上限同步抛出 Error，未接收该条消息。
- Node 尊重 socket.write 的背压状态，等待 drain 后继续。浏览器根据 bufferedAmount 暂停向原生 WebSocket 投递。1 MiB 是投递阈值，不是单帧上限。
- setImage 在发送堵塞时按 context 合并尚未投递的图片，仅保留最新帧。普通命令是顺序屏障，不跨命令合并，也不会撤回已交给传输层的帧。
- 10 秒没有发送进展时终止发送队列并关闭连接。SDK 队列立即释放；底层 socket/浏览器缓冲由对应运行时释放。Node 使用现有 close/onExit 生命周期，不自动重连。
- RPC 超时不会撤回已投递的消息。无 timeout 的 Proxy 仍保持原有无限等待行为，本改动不改变 RPC 契约。

16 MiB 是待发送数据字节上限，不是进程总内存上限：字符串、图像生成、JSON 编码和帧编码会产生额外临时开销。已经发送到宿主的业务处理积压也不在此队列的控制范围。

业务应捕获发送错误、暂停或降低画面刷新速率，不能遇到超限后紧密循环重试。若使用单张超过 16 MiB 的图像，应先降低编码体积。

验证命令：`npm run check`。测试覆盖队列限额、多 context 图片合并、命令顺序、堵塞超时、恢复发送、浏览器发送封装，以及真实 TCP 对端停止读取。
